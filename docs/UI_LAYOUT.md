│ ① 品牌行：⚡ 韧传 EverSend      │ ④ 会话顶部 PeerHeader                         │

│ 底部栏 SidebarFooter            │    已选文件以 chip 形式排在输入框上方           │
│    ▸ 传输（带进行中数量徽标）    │    PIN 框**只在对方要求 PIN 时出现**            │

**【2026-09 改】页面导航只有一个入口**：侧栏底部「传输 / 设置」。
主区顶部**不再有** `[会话｜传输]` 分段控件（那是同一页的第二个入口，已删）；
点设备行 = 回到该设备的会话，传输页第一行给 `← 返回会话`。

- 侧栏固定宽度、不随窗口缩放：电脑端 **288 px**，网页版宽屏 **288 px**，安卓宽屏
  **300 dp**。侧栏与主区之间是 1 px 竖线（`border-right`），不是卡片、不圆角。
- 主区吃掉剩余全部宽度，**大面积**留给会话；主区内部上下分三段：顶部信息、
  中间内容、底部输入。
- 窄屏（网页版手机、安卓手机竖屏）没有 288 px 可放：侧栏收成**抽屉**
  （网页版：`≤ 720px` 时抽屉 + 左上角 ☰；安卓：`ModalNavigationDrawer`），
  但**内容顺序与宽屏完全一致**，且抽屉里仍然是「设备操作在顶部、设备列表在中间、
  传输/设置在底部」。

## 2. 侧栏三段（从上到下）

| 位置 | 内容 | 要求 |
|---|---|---|
| 顶部 ① | 品牌行 | 图标 + 「韧传」+ 小字 EverSend；第二行小字写**本机名**和本机地址（让别人能照着手输） |
| 顶部 ② | 设备操作 | **【2026-09 改】一行三个按钮：`扫描`（带下拉）、`连接手机`、`群聊`。**<br>原先是五个平级图标按钮（刷新 / 扫描 / 手动添加 IP / 手机连接 / 新建群聊）。其中**刷新与扫描是同一个意图**（都是"催一次发现"），已合并成一个 `扫描`：点一下先催公告，没有应答就自动升级为主动扫描；**手动添加 IP 收进 `扫描` 的下拉**；下拉里原本还有一个"用二维码连接"，与 `连接手机` 同义，已删。**这里不再有「＋ 发送文件」** —— 选文件只有输入区那个「📎 传输文件」（外加把文件拖进会话区）：文件和"发给谁"绑在一起，入口就只留一个 |
| 中部 ③ | 设备列表 | **分成「在线」「离线」两段**，每段标题可点、整段展开或折叠（标题左边一个 ▾/▸，右边是数量徽标）：<br>· **在线**（默认展开）：现在就能收发的设备；<br>· **离线**（默认折叠）：上次见过、现在不在线的设备。离线这一栏有三类来源：**本机记住的身份快照**（走过一次就记住，落盘在 `known_devices.json`，最多 24 台 / 24 小时）、配对过但没连着的手机、以及有会话记录的历史设备。点开还进得去历史会话。<br>每台设备一行：头像、名字、状态徽标、副标题（地址 · 端口 · 发现方式/在线时长）；点一行 = 选中它，「会话」页立刻切成和它的对话；右键/长按出「忘记这台设备」等菜单。选中的设备落在折叠着的那一段时，自动把那一段展开。<br>**高度规则**：折叠的那一段只占一行标题的高度、紧贴「设备列表」标题下边（下面那一段立刻跟上来）；展开的那一段按内容定高，上限由**窗口高度减去侧栏里其它东西的实际高度**算出来（不写死常数）—— 超出上限就在列表内部滚动。两段都不吃弹性空间：余下的高度落在两段下面，群聊与底部「传输 / 设置」照旧贴底，任何窗口尺寸下都不会被挤出窗口。 |
| 底部 | 传输 / 设置 | 两项导航，固定在侧栏底部（列表再长也压不下去）；「传输」右侧显示进行中的数量徽标 |

群聊不是设备：群聊条目接在设备列表**下面**，用一条细分隔线与设备分开，
标题是「群聊」。没有群聊时不显示这一段。

## 3. 主区三段的细节

### ④ 会话顶部 PeerHeader（对方设备详细信息）

必须有：对方**名字**、**平台**（Windows/Linux/安卓/浏览器）、**设备 id 前 8 位**、
**地址 + 端口**、**发现方式**（组播/网页客户端/手动）、**在线状态**（在线 / 已离线 N 分钟前）、
**是否已信任**、**是否需要 PIN**。没有选中设备时显示占位文案（「从左边选一台设备」），
但 ⋯ 菜单仍在，保证「传输」页永远进得去。
（**【2026-09 改】**设备列表的副标题**不放端口** —— 端口对用户没有意义，
同一台机器上看到多个端口更糊涂；端口只留在这一行的详情里。
副标题只放**一个**事实：在线设备放地址，离线设备放平台 + 最后在线时间。）

右侧放：

- **【2026-09 改】不再有分段控件** —— 页面切换由侧栏底部导航承担（见 §1 的改动说明）。
- 右侧只留一个 **⋯ 溢出菜单**：`打开接收文件夹`、`清空会话`（会话页）/ `清空记录`（传输页）等
  都收在里面。**每一页头部最多一个主按钮 + 一个 ⋯**，不允许三个平级按钮排成一排。

### ⑤ 会话内容 SessionBody

- **会话页**：消息气泡列表，自己发的靠右、对方发的靠左；文件/图片/视频/语音长在气泡里
  （沿用现有实现）。列表底部自动滚动；顶部显示「对方正在传文件」之类进度时，进度写在气泡里。
- **传输页**：顶部一个分段控件 `[接收｜发送]`，下面是一张表格：

| 接收表格列 | 发送表格列 |
|---|---|
| 文件（名字，可点开） | 文件（名字） |
| 来自（设备名） | 发给（设备名） |
| 大小 | 大小 |
| 进度（百分比 + 进度条） | 进度（百分比 + 进度条） |
| 速度 · 剩余时间 | 速度 · 剩余时间 |
| 时间 | — |
| 状态（已完成/接收中/已拒绝/失败） | 状态（传输中/已完成/已取消/失败） |
| 操作（打开 / 在文件夹中显示） | 操作（取消 / 重试 / 移除） |

  > **2026-10-17（opt-1017）**：接收表补齐「进度 / 速度 / 剩余」三列，与发送表、网页端、手机端一致；
  > 100% 之后到收尾完成之前显示「校验中…」（不再继续显示"传输中"和衰减的速度）。

  - 两张表**共用同一块区域**，点分段控件就地切换，不跳页、不弹窗。
  - 表头固定、可点列头排序；行可滚动；进行中的行实时刷新（进度、速度）。
  - 空表要有空状态文案（「还没有收到文件」/「还没有发送过文件」）+ 一个主按钮。
  - **【2026-09 改】页头是两行，不是一行**（一行放不下就会互相重叠、把搜索框压扁）：
    - 第一行：`← 返回会话` + `[接收｜发送]` + 右侧 `⋯`（打开接收文件夹 / 更改接收位置 / 清空记录）；
    - 第二行：`[全部｜进行中｜已完成｜失败]` 筛选药丸 + 搜索框（**吃掉剩余宽度**）+ `打开接收文件夹`。
  - **筛选药丸必须真的筛**（空表要跟着筛选走，不能让用户点了药丸还是看到全部）。
  - **失败行要行内可重试**：状态是红药丸 `失败`，`操作` 列给一个「重试」按钮，
    并在行内/悬停里给出**中文原因**（对方拒绝 / 超时 / 磁盘满 / 校验失败…）。
  - **一个文件只占一行**：进行中的行与完成后的行是**同一行**（键见宪章 §4.5），
    不许出现"正在传"和"已完成"两行。

### ⑥ 输入区 Composer（只在会话页出现）

分两行，**输入框那一行永远贴着最底**：

1. **待发区（上面那一行）**：每个选好的文件是一块「图标/缩略图 + **底部文件名**」的方块 ——
   图片给真缩略图、视频给封面帧、其余给类型图标（文本 / 压缩包 / 普通文件 / 文件夹）；
   方块右上角一个小 ✕（不发送这个），**点方块就是预览**（见 §7）；方块多了横向滚动。
   这一行**最右边**是统计：「共 N 项 · X MB」。没有文件时这一行只剩一句拖放提示。
2. **输入行（最下面那一行）**：`📎 传输文件`、`😊`、输入框（占满剩余宽度）、PIN（窄）、`发送`。
   手机上这一行放不下时，工具按钮与 PIN 折到上一行，**输入框 + `发送` 仍然留在最后一行**。
3. **表情面板（默认收起，点 😊 展开）**：格子要够大 —— 电脑端按钮 44×42、字形 26px；
   网页版格子 ≥46×46、字号 26px；安卓格子 ≥48dp、字号 26sp（安卓三个地方共用同一个
   常量）。一行按可用宽度自适应（宽窗口一行二十来个，手机一行六七个）。
4. **emoji 字号统一**：**面板里挑的时候多大，发出去就该多大** —— 消息气泡、附件说明、
   文件名里的 emoji 都用同一个字号（桌面端 26px、网页版 26px、安卓 30sp），中文仍是
   正文大小。按码位切段，零宽连接符（👨‍👩‍👧）、变体选择符（✅）、肤色、国旗（区域指示符
   成对）算一段，不会被拆成几个"半个表情"。
   *输入框例外*：安卓用 Compose 的 `visualTransformation` 能把输入框里的 emoji 也放大；
   电脑端是 `QLineEdit`、网页版是 `<input>`，两者都不能逐字改样式 —— 那两处的输入框
   保持正文字号，发出去之后才是大号。
   它**不是弹窗**，而是输入区里的一块内嵌面板 ——
   宽度和输入框那一行一样（占满输入区宽度），位置**紧贴待发文件那一行的上边**：
   `[表情面板] → [待发文件 + 统计] → [输入行]`。再点 😊 收起；点一个表情就插进输入框，
   面板不关（可以连着挑几个）；面板有高度上限，超出就在面板里滚动。

回车 = 发送；拖放到会话区任意位置 = 加入待发。选中的设备数 >1 时，`发送` 按钮写「发送到 N 台」。

## 4. 交互与状态约定

- **选中设备**是全局状态：侧栏选中行、主区顶部信息、输入区目标三者永远一致。
- **离线设备不是发送目标**：选中一台离线设备时「发送」是禁用的（它没有可用的地址），
  三端一致 —— 一条发不出去却显示"正在发送"的传输，比一句"它不在线"更糟。
- **一条开着的 SSE 事件流 = 在线**：服务端每 `CLIENT_TTL/2` 碰一次客户端。手机端的保活服务
  把流挂上之后就不会再发离散请求，只按"请求才算在线"会把一台连着的手机判成离线
  （web selftest 里有 4 项回归检查盯着这条）。
- **【2026-09 改】页面导航只有一个入口**：侧栏底部「传输」。
  原先顶部 `[会话｜传输]` 分段控件与它指向同一页，是第二个入口，**已删**。
  点设备行 = 回到该设备的会话；传输页第一行给 `← 返回会话`。
- **设置**不占侧栏中间的位置：点侧栏底部「设置」把**主区**换成设置页（侧栏仍在），
  设置页顶部有返回会话的 `←` 或点任意设备回到会话。
- 侧栏底部「传输」在有进行中的传输时显示数量徽标，传完自动消失。
- 所有既有功能一个都不能少：发送文件/文件夹、多选设备群发、PIN、扫码、
  接收确认弹窗、断点续传进度、接收历史、聊天（文字/表情/图片/视频/文件/语音/群聊）、
  主题切换、日志与状态栏提示。

## 4.5 传输记录 / 会话归属 / 文件动作（三端同一套语义）

- **一个文件只占一行**：文件落地之后，"正在传"那一行立刻收起来，只留「已完成」那一行
  （它带全部动作）。收起是**隐藏**不是删除 —— 删除会让下面所有行的下标上移，而活动
  传输行是按下标持有单元格句柄的，删一行就可能让另一条传输去更新别人的行。
- **传输记录也进会话**：走「传输文件」这条路的收发（不是聊天附件）会在会话里留一条
  记录（方向 / 文件名 / 大小 / 状态：发送中 → 已发送 / 失败），**进度长在那条消息下面**；
  聊天附件本来就有气泡，不重复记（判据：文件路径是否在 `media/<会话>/` 下）。
- **同一套文件动作**：会话卡片、传输表的历史行、待发方块右键都是
  `预览 / 打开 / 打开所在文件夹 / 另存为…`。手机端没有"右键"，用**长按**；网页版没有
  "打开所在文件夹"这个概念，那一项换成**下载**并在提示里写明（不是漏做）。
- **一台设备只有一段一对一会话**：同一台手机在会话里的成员写法可能有好几种
  （App 的设备号、浏览器的 `地址|UA 摘要`、早期没带设备号时的 `地址:空摘要`）。
  写法一变消息就落进另一个会话，用户看到的是"电脑上不显示消息"。所以：
  新消息一律用规范写法（`web:<设备号>`）登记；启动时把**能证明是同一台设备**的几段
  并回一处（同一地址上有多台设备时不并 —— 宁可留两段，也不能把两台手机并成一台）。
- **一台设备只能有一个身份**：服务端给每条客户端记录一个稳定字段 `identityKey`
  （有设备号就是 `web:<deviceId>` / `android:<deviceId>`，与地址无关；确实没有设备号的
  老式浏览器退回它自己的键 `地址|UA摘要`）。**`identityKey` 相同 = 同一台物理设备，
  三端列表只留一行**。会被自动归并的形态：页面首次加载（浏览器加不了自定义头）留下的
  `地址|UA摘要` 影子记录 ↔ 之后带 `X-EverSend-Device` 的 `web:<uuid>` 记录；同一设备号
  从不同地址报到。**不会**归并：同地址上的另一个 UA（另一款浏览器）、两台设备号不同的
  手机 —— 宁可留两行，也不能把两台设备并成一台。归并掉的旧键记进 `aliases`（含当时的
  显示名 `aliasLabels`），老会话的标题因此不会变成"未知设备"。
- **离线列表可以清空**：电脑端在设置页「设备列表」那张卡片里（写着"离线那栏现在有几台"）
  + 侧栏「离线」标题右键；网页版在「离线」段的标题行（手机上长按）；安卓在设置页。
  服务端接口是 `POST /api/devices/forget-offline`（返回清掉几台）。
  清空只去掉**本机记住的**「以前见过」名单（电脑端连 `known_devices.json` 一起清），
  **不动聊天记录、不动配对关系**；有聊天记录的设备行不会跟着消失 —— 那种行是打开
  那段会话的唯一入口。
- **合并会话有强弱两条规则**：
  · **弱（启动时自动）**：只有能证明是同一台设备的证据才并 —— 客户端自报的设备号、
    注册表键、同一地址上唯一的 App 客户端。
  · **强（设置页「整理重复会话…」，用户确认后执行）**：再加上 **UA 指纹**，把同一款
    浏览器在不同地址上的记录认成一台；执行前会把"保留哪段、并掉哪几段、依据是什么"
    列出来让用户过目。代价写在同一句提示里：两台一模一样的手机也可能被并到一起。
  · 一段会话里出现多个"对方"写法时，这几条证据链会被**接起来**（桥接），否则本该
    合并的两段会因为各自认了不同成员而分在两个组里。
- **"发给几台"只数看得见的**：折叠着的那一段设备列表里可能还留着上一次的选中项，
  它既看不见、又不该算进发送目标 —— 收起那一段时清掉选中，计数时也只数可见的行。
- **自己发给自己的文件不再要确认**：手机上"发给这台电脑"走的是本机回环（网页端的
  `self_peer`），接收侧必须自动放行 —— 否则文件卡在 `.part` 里，用户那边是"手机说发出去了，
  电脑上什么都没收到"。放行条件必须是**设备号等于本机 + 连接来自回环**两条同时成立，
  否则局域网里谎报设备号就能绕开"接收前先问我"。
- **等你点接收的弹窗不能被漏掉**：弹窗抬到最前 + 状态栏写明"某某想发 N 个文件给你"，
  并让任务栏闪一下。
- **"自动打开"不等于"用户看过"**：程序替用户恢复/改开某段会话时**不标已读**
  （`open_conversation(..., mark_read=False)`），只有用户自己点进去才算看过；
  未读是三端共用的 chat.db，一启动就清掉会让用户以为漏看了消息。
- **整理重复会话必须自己排一次**：不要依赖"会话列表变化"这个信号 —— ChatView 在
  构造时的那次广播发生在 bridge 接上之前（丢了），安静的启动里自动整理根本不会跑。
- **放弃的传输要回收磁盘**：取消/放弃的接收要立刻删掉预分配的 `.part`（并清 journal），
  启动清理要扫**接收目录**（不只是 `data_dir`）；"中断"（关应用、链路断开）才保留
  `.part` + journal 供续传。
- **打开失败要说出来**：`xdg-open` 之类的"进程起得来但退出码非 0"以前被当成成功，
  现在 `open_path()` 会返回失败并给出可显示的文案，桌面端接到状态栏。
- **预览按窗口缩放**：图片预览的"适应窗口"必须把图缩到可视区以内（图比可视区小就
  不放大），点一下才切原始大小。

## 5. 各客户端的实现位置

| 客户端 | 侧栏 | 主区 | 传输表格 |
|---|---|---|---|
| 电脑端 | `desktop/sidebar.py` | `desktop/session_view.py`（PeerHeader + 会话）、`desktop/transfers_view.py` | `QTableWidget`（`desktop/widgets.py` 的 `TransferTable`）；预览在 `desktop/preview.py` |
| 网页版 | `web/assets/index.html` `.sidebar` | `.main` / `.peer-header` / `.composer` | `<table>` + `.seg` 分段；预览用页内弹层 |
| 安卓 | `MainActivity.kt` 的 `AppSidebar` | `PeerHeader` / `ChatPane` / `TransfersPane` | Compose 表格式行；预览用 Dialog |

### 网页版做不到的三件事（写在这里，免得下次又当 bug 修）

浏览器里跑的这一版**没有**「打开接收文件夹 / 更改接收位置 / 清空记录」这三个动作：
浏览器打不开电脑的文件管理器，接口层也没有这两个写操作。所以它页头给的是「刷新」。
同理，「接收」表里只会有**正在进行**的传输 —— `/api/state` 不报历史，
已经收完的东西落在页面下方那两张列表里。这不是漏做，是网页版的能力边界。

### 列宽可以不一样，事实必须一样

三端的表格列允许按屏幕宽度合并（手机网页把「速度」和「剩余」并成一列，电脑端分成
两列；电脑端接收表有「打开所在位置」，手机只在附件气泡里给「保存」）。判断标准只有
一条：**上面那六项事实在每一端都能看到**，缺一项才算没做完。

## 6. 文件预览（三端一致）

点这三处都会打开预览：**待发方块**、**气泡上的「预览」**、**接收表历史行的「预览」**。
以前只有图片能"点开看大图"，其它类型只能丢给系统程序 —— 现在先在这里看一眼。

| 文件类型 | 预览里给什么 |
|---|---|
| 图片 | 铺满窗口，点一下在"适应窗口 / 原始大小"之间切换，可另存为 |
| 视频 | 封面帧（有 FFmpeg 就是真的一帧）+ 「▶ 播放」+ 时长 |
| 音频 / 语音 | 「▶ 播放」+ 时长 |
| 文本 / 代码 | 前 256 KB 等宽只读，可选中；超出就在末尾说明"只显示开头一段" |
| 其它二进制 | **不装作能看**：类型图标 + 名字 + 大小 + 「用系统程序打开 / 在文件夹中显示 / 另存为」 |

判定顺序：**扩展名优先，再闻内容** —— 前 4 KB 里有 NUL 字节，或者命中
zip/gzip/PNG/JPEG/PDF/ELF/SQLite/rar/7z 这些魔数，就按二进制处理；
其余尝试按 UTF-8 解码，解得开就当文本（``README``、日志、配置这些没有后缀的文件
也能看）。同一份判定要三端一样，否则同一个文件在一端能看、另一端说"看不了"。

播放这件事各端能力不同（电脑端的绿色包没有 QtMultimedia、浏览器不能开本机程序），
但**都必须给一个真的能用的入口**，并在界面上写明是内置播放器还是系统播放器。

## 7. 不许回退的既有约定

- 测试与文档里已有的**用户可见文案**尽量保留（「设备列表」「会话」「传输」「接收」
  「发送」「设置」「电脑发来的文件」等），改名的同时要改测试与 README。
- 三个客户端的接口（HTTP 路由、SSE 事件、桌面端 `EngineBridge` 信号）**不改**：
  这次只动界面。
- 桌面端 `MainWindow` 上被测试直接调用的名字（`device_table`、`_add_paths`、
  `_send`、`_transfers`、`_add_transfer_row`、`theme_combo`、`status_left`、
  `settings_path`）保持可用；`tabs` 这种被布局取代的，改成 `show_page("chat")`
  这样的显式方法，并同步改测试。
