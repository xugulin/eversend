## 0. 验收口径：用户原话 → 可判定的结果

用户报的每一条都必须在下面的表里找到对应的"做完的样子"。**没做到就是没做完，
不许用"已经实现了"来结案** —— 本项目历史上已经出现过"文档说修好了、界面上还在"。

| # | 用户原话 | 做完的样子（可判定） |
|---|---|---|
| C1 | 有功能重复的按钮 | 全项目**没有任何两个控件触发同一个用户意图**。判定法：把每个按钮/菜单项列出来，能合并的合并，能删的删。三端一致 |
| C2 | 排版丑陋不美观 | 全部间距落在 4 的倍数、字号取类型刻度、圆角/描边来自 token；截图看不出"挤在一起"或"空旷失衡"；对齐线只有一条 |
| C3 | 操作逻辑繁复无意义 | 完成"发一个文件给一台设备"≤ 3 次点击（选中设备 → 传输文件 → 发送 / 回车）。没有必须理解才能用的隐藏前置条件 |
| C4 | 核心的连接设备显示乱、同一设备重复显示 | 同一台物理设备在列表里**永远只有一行**；名字不被截断（按字素省略 + 悬停显示全名）；副标题只放"是什么/在哪/怎么发现的" |
| C5 | 传输页 GUI 杂乱、信息不明不详细 | 传输页有筛选（全部/进行中/已完成/失败）、有列头、有排序、有空状态；每一行说清：文件、对端、大小、时间、进度、速度、剩余、结果；失败行给出**原因**与"重试" |
| C6 | 对文件的操作处理不完整 | 任何一处出现文件（气泡附件、待发方块、传输表行、接收历史）都给同一套动作：预览/播放、打开、打开所在文件夹、另存为…、复制路径、复制文件、删除本地文件、重新发送、属性（名字/大小/类型/路径/时间/SHA-256）。能力边界（网页版没有"所在文件夹"）要写明而不是缺项 |
| C7 | 垃圾记录堆积 | 记录按身份去重；有保留策略（默认保留最近 N 条 / D 天，可配置）；`清空记录` 一次清干净；没有孤儿行、没有 `__pending__` 泄漏、没有空名字设备行 |
| C8 | 同一个文件传到同一设备显示两次 | 一个文件在一张表里**只占一行**；同一 (方向, 对端, 内容) 的重复投递合并成一行并累加状态，不新增行 |
| C9 | 乱显示设备连接信息 | 设备行/详情里的每个字段都有唯一出处，不重复展示同一个事实（不要在标题、副标题、详情行里写三遍地址） |
| C10 | 中文软件选文件弹窗是英文 | 全应用（含 QFileDialog、QMessageBox 标准按钮、右键菜单、输入法上下文菜单）**不再出现任何英文系统文案**。做法：安装 Qt 自带 `qtbase_zh_CN.qm` + `QLocale` 显式设为中文；绿色包必须把 `.qm` 一起打进去；缺翻译时退回 `DontUseNativeDialog` 的自绘对话框兜底 |
| C11 | 传输预览功能问题多、显示丑陋 | 预览窗口按 §6 的类型矩阵工作；图片适应窗口/原始大小切换正确；视频给真封面帧；文本等宽可选中；二进制不装作能看；窗口有标题栏、工具栏、"另存为/打开/在文件夹中显示"，无重叠无抖动 |
| C12 | Web 版显示复杂杂乱、操作逻辑混乱 | 网页版复用同一套 IA 与 token：侧栏在宽屏固定、窄屏抽屉；主区只有"会话/传输"两种内容；没有嵌套三层以上的容器；所有动作都能在两次点击内到达 |
| C13 | PC 与安卓不能自动扫描连上，要手动输 IP | 同一局域网内，两个客户端在 **≤ 5 秒**内自动互相出现，**不需要任何手动操作**；`扫描` 按钮只是加速手段而不是必需步骤；自动发现失败时界面明说"为什么"（防火墙/不同网段/客户端隔离）并给一键排查 |
| C14 | 局域网内传输文件、发送消息会失败不显示 | 消息投递有确认与重试；失败进"待重发"队列并在界面上可见（红色标记 + 重试）；不会出现"发出去了但对面没有"。传输失败给出原因码 |

**额外硬要求（企业级基线）**

- **E1 三端一致**：同一事实在三端用同一套措辞、同一套语义（列宽可不同）。
- **E2 可观测**：设置页有"诊断"卡片：本机地址、监听端口、发现通道状态（组播/广播/主动扫描各成功几次）、最近错误。出问题用户能自己截图发出来。
- **E3 无静默失败**：任何失败都必须有一个用户能看到的界面反馈（状态栏/toast/行内红字），并带可执行的下一步。
- **E4 无回归**：现有 200+ 网页自检、GUI 渲染/交互测试、内核与恶劣网络测试**必须继续全绿**。
- **E5 性能**：窗口冷启动 ≤ 1.5s（本机）、切换页面无可感卡顿、1000 条传输记录滚动流畅（用 `QTableView` 或分页，不要 1000 个 widget）。
- **E6 交付质量**：`README.md` 里**每一条本地图片引用都必须能解析** ——
  README 是用户看到的第一份东西，一张打不开的图比没有图更糟
  （`![]()` 在 GitHub 上会渲染成一个破图占位符）。
  可复跑：`.venv/bin/python tests/test_enterprise_acceptance.py --only E6`；
  对照表：`tests/reports/readme_screenshots_audit.md`。
  **两张目录的语义不许混**：
  | 目录 | 用途 |
  |---|---|
  | `docs/screenshots/` | **README 画廊**（三端都放，靠前缀区分：桌面 `NN-*.png`、网页 `web-*.png`、安卓 `android-app-*.png`、QA 补充 `qa-*.png`） |
  | `tests/screenshots/` | **测试产物**（`test_gui_render.py` 的输出、前后对照 `*-before.png`），README 不引用 |
  重拍画廊的正式做法：`EVERSEND_SHOT_DIR=docs/screenshots xvfb-run -a -s "-screen 0 1280x900x24" .venv/bin/python tests/test_gui_render.py`
  （渲染脚本**只往 `EVERSEND_SHOT_DIR` 写**，所以这一步就是重拍画廊，不是"跑错了目录"）。

## 1. 六条铁律

1. **一个意图，一个入口。** 出现第二个入口就删掉它，并同步改测试与文档。
2. **全中文。** 用户可见的每一个字都是中文，包括操作系统对话框。
3. **一行一事实。** 同一个事实不在同一个界面里出现两次。
4. **4 的倍数。** 所有 padding/margin/gap 取 4 的倍数；字号取类型刻度。
5. **不许静默失败。** 没有反馈 = bug。
6. **列表按身份去重。** 去重键是稳定身份（`deviceId` / `identityKey` / 内容摘要），不是显示名、不是地址。

## 4.5 传输记录去重与保留（对应 C7 / C8）

> 这一节由 records-data 在实现中定稿、Lead 收录。它是**数据层契约**：
> 三端的表格/列表都必须用同一套键，**不许各自做字符串去重**。

**去重键**

```
transfer_record_key(direction, peer_identity, content_identity)
```

- `direction`：`"in"` / `"out"`。
- `peer_identity`：1:1 会话里"不是我"的那个成员 id；群聊 = 会话 id；
  调用方可显式传 `peer=`。**不是显示名、不是地址** —— 名字会改、地址会变。
- `content_identity`：**优先内容摘要**（调用方给 `digest=`，或 ≤64 MiB 直接算 blake2b；
  net-discovery 在 `file_done` 事件里给整文件摘要）。算不出摘要时退回
  `f:size:mtime_ns:name` 兜底。**绝不只按文件名** —— 同名不同内容必须是两行。
- 落库位置：`messages.record_key`（32 位 hex），老库自动 ALTER 迁移，原样可用。

**合并语义（这是 C8 的判定依据）**

| 情形 | 结果 |
|---|---|
| 同一次投递先写 `sending`、再写 `sent` / `failed` | **同一行**，`attempts = 1` |
| 重复发送同一个文件到同一台设备 | **合并成一行**，`attempts` 累加，**不新增行** |
| 同名但内容不同 | **两行**（内容是摘要） |
| 同一 `transfer_id` 建两次 | **一行** |
| 纯文本消息 | **不去重**（连发两句"你好"就是两条） |
| `record_key` 为空且无身份的行 | **拒绝创建**（从源头堵掉 0 宽度行） |

`attempts` 计数规则：写"进行中" +1；写终态而原来在进行中 → 不加（这一次刚结束）；
写终态而原来已是终态 → +1（又一次投递）。

**保留策略**

- `prune_records(keep=500, days=30)`：**开库时 + 写入时**（5 s 节流）自动跑；
  只修剪**账本**（媒体 / system 行），不动会话正文（正文仍按 `limit_messages` 单会话封顶）。
- `converge_stale()`：开库时把 >15 分钟的"进行中"行收敛为 `failed` ——
  进程刚起来时本机不可能有在飞的传输。这消灭了"永远转圈的行"。
- `chunkstore.ResumeIndex.sweep` 必须**递归**（上限 `SWEEP_MAX_DEPTH=4`）：
  聊天附件落在 `接收目录/韧传聊天/<hash>/`，`.part` / `.journal` 在两层以下，
  只扫顶层就永远收不到 —— 那是"孤儿 `.part` 堆积"的真实来源。

**设备记录（对应 C4 的"同一设备重复显示"）**

- 去重键是 `deviceId` / `identityKey`，**不是显示名**。
- `prune_device_records(records, now, offline_ttl=DEVICE_RECORD_TTL, limit=DEVICE_RECORD_LIMIT)`
  回收幽灵行，规则要能自证：①同 address + 同 port 且旧行离线 > TTL（端口被新实例接管）；
  ②同 address + 同 platform 且旧行离线 > TTL（重装 / 换数据目录）；
  ③没有可寻址身份或 `__pending__` 占位；④超上限时的**离线**行。
  **从不回收刚见过的行**；每次回收都带 `{key, reason, survivor}`。
  **不过度合并**：platform 不同 → 不回收；没有 port/platform 的浏览器记录 → 不回收。
- 三台**同时在线**的同名设备是三个真实实例，数据层不能删（无法自证）——
  正确处置是**展示层消歧**：`model.disambiguate_names(devices) -> dict[device_id, str]`
  （在线优先 → lastSeen → id 定序，结果与遍历顺序无关；第一个保留原名，其余 `RealProbe #2` / `#3`）。
  纯展示、不改数据，**三端共用这一个函数**。

## 5. 网络与发现（对应 C13 / C14）

**目标：同网段两个客户端 ≤5s 自动互相出现，零手动操作。**

1. **启动即公告**：`ANNOUNCE_DELAYS` 首包 ≤ 300ms，之后 1s/2s/5s 退避，稳态 15s。
2. **离开即公告**：关闭前发一条 `bye`，对端立刻转离线（不要等 TTL）。
3. **四通道合流**：组播 → 广播（含每个接口的定向广播）→ 主动 /24 扫描 → 手动/二维码。
   任一通道先到就用哪个；**主动扫描要覆盖所有本机网段**（不只 /24，含 /16 的分段抽样），
   并且节流到不刷爆交换机。
4. **发现失败要能解释**：设置页诊断显示三个通道各自的成功率与最后一次错误；
   界面上给"为什么看不到对方"的排查清单。
5. **消息必达**：`SYNC`/消息投递要求对端 ACK；无 ACK 进重发队列（指数退避，上限 5 次），
   队列可见、可手动重试、可放弃。对端离线时立刻返回"对方不在线"而不是静默丢弃。
6. **传输失败要有原因码**：连接被拒 / 超时 / 磁盘满 / 校验失败 / 用户取消 —— 界面显示中文原因。
   失败行必须**行内可重试**（一个「重试」按钮，不是只有右键菜单里才有）。
   > **口径澄清（`enable_scan`）**：`enable_scan` 关的是**自动轮次**（用户嫌它吵），
   > **不是**让手动「扫描」按钮失效 —— 手动扫描是兜底路径，必须始终可用。
   > 所以"关掉自动扫描 → 候选为空"**不是**契约；
   > 契约是"关掉自动扫描后，手动点「扫描」仍然能发现对端"。
7. **重连要自动**：TCP 断开后按 1s/2s/4s/8s 重连，恢复后自动续传与补投消息。

### 5.1 主动扫描兜底的实测证据（Lead 独立复现，勿删）

"用户说必须手动输 IP"对应的场景是：**组播、广播、mDNS 全被网络拦掉**，
只剩主动扫描这一条通道。这条通道**实测有效**，方法如下（复现脚本 `/tmp/lead_scan3.py`）：

```bash
cd eversend
unshare -rn bash -c '
ip link set lo up
ip link add v0 type veth peer name v1
ip addr add 10.99.1.1/24 dev v0
ip addr add 10.99.1.2/24 dev v1
ip link set v0 up; ip link set v1 up
.venv/bin/python /tmp/lead_scan3.py
'
```

结果：

```
UDP 全封、只留主动扫描 → A 发现 B 耗时: 2.16s
A 看到: [('Lead-B', 'scan', '10.99.1.1')]
扫描通道: attempts=254 successes=2 errors=0 healthy=True
```

对照：组播 / 广播 / mDNS 可达时是 **0.01～1.8 s**。

**两个必须记住的测试陷阱**（我第一版就是被它们误导，差点把好代码当 bug 报）：

1. **`tcp_port=0` 会让两端拿到不同端口**，扫描去探本端的端口自然探不到对端。
   真实世界两端都用同一个默认端口，测试时必须显式对齐端口。
2. **扫描按设计跳过本机地址**（`discovery.py` 里 `if host == own: continue`，loopback 也跳过）。
   所以**同一台机器上跑两个 Engine 永远测不出扫描通道** —— 必须用 veth 对（或两台真机）
   造出一个"不是本机地址但可达"的探测目标。

这条配方依赖 `netns`，**不要进 CI**；CI 里用"候选面 + 桩 `_probe`"的等价断言
（见 `tests/test_enterprise_acceptance.py` 的 `C13b`）。

## 6. 预览（对应 C11）

按 `UI_LAYOUT.md §6` 的类型矩阵执行，并补齐：

- 窗口：标题 = 文件名；工具栏 = `缩小(缩放-) / 放大(缩放+) / 适应窗口 / 原始大小 / 上一张 / 下一张 / 另存为 / 打开 / 在文件夹中显示`
  - **口径更正**：`缩放- / 缩放+` 与 `缩小 / 放大` **两种写法都合规**（前者是尺度、后者是动作，后者配 tooltip 说清"以鼠标位置为中心"更好懂）。判定只看**动作是否存在且能用**。
  - 「适应窗口 / 原始大小」必须有**可见的当前状态**（按钮 checked 态或信息行文字），不能让人看不出现在是哪种模式。
- 图片：适应窗口（不放大超过 100%）↔ 点击切换原始大小；滚轮缩放以鼠标为中心；拖拽平移
- 视频：真封面帧（有 FFmpeg）+ ▶ + 时长；点播放调用系统播放器或内置播放器（界面写明用哪个）
- 文本：前 256 KB 等宽只读、可选中、可复制；超出在末尾说明
- 二进制：类型图标 + 名字 + 大小 + 三个动作，不装作能看
- 键盘：`Esc` 关闭、`←/→` 上一张/下一张、`Ctrl+S` 另存为、`Ctrl+0` 适应窗口、`Ctrl+1` 原始大小。
  **判定方式是行为**：真的发一次按键，看有没有效果 —— 按钮文案里画个「（←）」不算，按下去要有反应。
  （`QShortcut` 只是常见实现手法，不是判据；走 `keyPressEvent` 同样合规。验收看的是用户按了有没有反应。）
  细节：图片拖拽平移进行中时 `←/→` 不翻页；文本预览模式下把 `←/→` 留给光标，只在焦点不在文本框时翻页（各端自己权衡，但要在文档里写明选择）。
- 打开期间不得阻塞主窗口超过 100ms（大图解码放工作线程）
